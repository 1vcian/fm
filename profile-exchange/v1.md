# fm profile exchange, version 1

How another app reads a player's profile on [1vcian.me/fm](https://1vcian.me/fm/) and sends it updates.

## How a player links your app

1. On the site, the player opens **Profile > Settings > Linked apps** (signed in; while the feature is
   in preview the page must be opened with `?debug=1`, e.g. `https://1vcian.me/fm/?debug=1`), names your app,
   picks *Can read* and/or *Can send updates*, and presses **Make a key**.
2. The site shows the key once, e.g. `fmk1_3f9c…` (`fmk1_` + 48 hex characters). The player
   pastes it into your app. That key is the whole authentication: one key = one profile.
3. The player can make a new key (the old one stops working) or revoke it at any time. Then
   your calls answer `failed`: ask the player for a new key.

Your app ships no secret. Every call also carries the project's **publishable key** (the
`apikey` header below). It is public by design (the website itself sends it) and unlocks nothing
without a player's key. The site owner gives it to you, and it does not change per player.

## Calls

Two HTTP `POST` calls, JSON in and out. Base URL and function names are also in
[`versions.json`](versions.json).

```
POST https://cwnrucmlxzxzoamyjbhq.supabase.co/rest/v1/rpc/profile_link_push
apikey: <publishable key>
Content-Type: application/json

{ "p_token": "fmk1_…", "p_format_version": 1, "p_data": { …the document below… } }
```

```
POST https://cwnrucmlxzxzoamyjbhq.supabase.co/rest/v1/rpc/profile_link_read
apikey: <publishable key>
Content-Type: application/json

{ "p_token": "fmk1_…" }
```

Both answer HTTP 200 with a `status`:

| status | meaning |
|---|---|
| `ok` | push: `push_id`, and `auto_apply` (true when the player applies your updates without reviewing). read: `profile.name` and `export` (below) |
| `failed` | the key is wrong, revoked, or its profile was deleted |
| `forbidden` | the key cannot do this (read-only key pushing, or the reverse) |
| `invalid` | `p_format_version` is not 1 to 1000, or `p_data` is not a JSON object (`message` says which) |
| `too_large` | `p_data` is over `max_bytes` (65536; a full document is about 3 KB) |
| `rate_limited` | over 60 pushes or 240 reads per hour for this key; retry after `retry_after_seconds` |

**A push is a proposal.** It waits on the site until the player reviews it (every change is
listed, values outside the game's limits are left out) and applies or dismisses it. A newer push
from the same key replaces a pending one, so send the whole current state, not a delta of the
last push. A player can switch on "apply without asking" for your key, which still drops values
outside the game's limits.

**A read** returns `export`: `{ "format_version": 1, "data": { …document… }, "updated_at": "…" }`,
the profile as the site last saved it in this format, or `null` when the site has not saved
one yet (the player has to open the site once after making a read key).

## The document

Every section is optional: what you leave out stays as it is on the site. Send only what you
read.

```json
{
  "format": "fm-profile",
  "version": 1,
  "source": { "app": "My scanner", "appVersion": "1.0.0", "gameConfig": "2026_10_27_09_45" },
  "items": {
    "Weapon": {
      "age": 9, "idx": 0, "level": 149,
      "substats": [ { "stat": "CriticalChance", "value": 11.5 }, { "stat": "AttackSpeed", "value": 38.2 } ],
      "skin": { "idx": 0, "type": "Weapon", "level": 3, "stats": { "Damage": 0.12 } }
    },
    "Ring": { "age": 9, "idx": 0, "level": 149, "substats": [ { "stat": "CriticalMulti", "value": 74 } ] }
  },
  "pets": [
    { "rarity": "Mythic", "id": 2, "level": 100, "ascension": 0, "substats": [ { "stat": "LifeSteal", "value": 18.4 } ] }
  ],
  "mount": { "rarity": "Mythic", "id": 0, "level": 100, "ascension": 1 },
  "skills": { "Meat": { "level": 100, "ascension": 0 }, "Arrows": { "level": 87 } },
  "forge": { "level": 34, "hammers": 125000 },
  "ascension": { "forge": 2, "skills": 1 },
  "currencies": { "coins": 1200000, "gems": 4500, "eggshells": 310, "skillTickets": 40, "clockWinders": 12, "guildPotions": 300 }
}
```

| field | what |
|---|---|
| `format`, `version` | always `"fm-profile"` and `1` |
| `source` | optional, shown to the player when they review: your app's name and version, and the game config you read with |
| `items` | equipped items by slot: `Weapon`, `Helmet`, `Body`, `Gloves`, `Belt`, `Necklace`, `Ring`, `Shoe`. A missing slot or `null` stays as it is |
| `items.*.age` | 0 to 9 (Primitive, Medieval, Early-Modern, Modern, Space, Interstellar, Multiverse, Quantum, Underworld, Divine): `Age` in `AutoItemMapping.json` |
| `items.*.idx` | the item's `Idx` in the game's `ItemBalancingLibrary.json` (keys `{'Age': 9, 'Type': 'Helmet', 'Idx': 0}`): that is the item's identity. To go from a name or an icon to the idx, `AutoItemMapping.json` (the site's own table, not a game config) lists every item as `"<age>_<type>_<idx>"` with its `SpriteName` and `LocalizationId` (type 0 Helmet, 1 Body, 2 Gloves, 3 Necklace, 4 Ring, 5 Weapon, 6 Shoe, 7 Belt). `LocalizationId` is text: some ids are past 2^53 and would round as numbers |
| `substats` | `stat` is a key of `SecondaryStatLibrary.json` (`CriticalChance`, `CriticalMulti`, `BlockChance`, `HealthRegen`, `LifeSteal`, `DoubleDamageChance`, `DamageMulti`, `MeleeDamageMulti`, `RangedDamageMulti`, `AttackSpeed`, `SkillDamageMulti`, `SkillCooldownMulti`, `HealthMulti`), `value` as the game shows it in percent: `11.5` for +11.5%. One entry per roll |
| `items.*.skin` | the skin on that item: `idx` and `type` (`Weapon`, `Helmet`, `Armour`) of its `SkinId` in `SkinsLibrary.json`, its `level`, and `stats` by stat type (`Damage`, `Health`) **as fractions**: `0.12` for +12% |
| `pets` | active pets in slot order, at most 3; `null` leaves a slot as it is. `rarity` is `Common`, `Rare`, `Epic`, `Legendary`, `Ultimate` or `Mythic`; `id` is the `Id` in `PetLibrary.json` for that rarity |
| `mount` | the active mount, same fields, `id` from `MountLibrary.json` |
| `skills` | levels by skill id (`Meat`, `Arrows`, `Shout`, `Berserk`, `Shuriken`, `CannonBarrage`, `Buff`, `RainOfArrows`, `Thorns`, `Morale`, `Bomb`, `Meteorite`, `Stampede`, `Worm`, `Lightning`, `HigherMorale`, `StrafeRun`, `Drone`: keys of `SkillLibrary.json`), with ascension stars |
| `forge` | forge level and hammers |
| `ascension` | forge and skill ascension stars |
| `currencies` | `coins`, `gems`, `eggshells`, `skillTickets`, `clockWinders`, `guildPotions` |

Whole numbers for ids, levels and stars; numbers of 0 or more for the rest. The site checks
every value against the game's own limits for its config version (item, pet, mount and skill
levels, ascension stars, one substat roll's maximum) and leaves out what is outside them.

The configs are published per game version: the list in
[`parsed_configs/versions.json`](https://1vcian.me/fm/parsed_configs/versions.json) (the first
entry is the newest), each file at `https://1vcian.me/fm/parsed_configs/<version>/<File>.json`.
`AutoItemMapping.json` and `Localization.json` (names in 14 languages, keyed by `LocalizationId`) are global, at
`https://1vcian.me/fm/parsed_configs/<File>.json`.

## Versions

[`versions.json`](versions.json) lists the versions the site reads (`supported`) and the newest
(`current`). A published version never changes. A game update that needs new fields gets a new
version next to it, and version 1 keeps working.
